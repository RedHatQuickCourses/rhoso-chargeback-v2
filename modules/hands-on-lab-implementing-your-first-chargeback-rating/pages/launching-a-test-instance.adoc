# Launching a test instance to generate consumption data

In this unit, you will launch a test instance on your Red Hat OpenStack Services on OpenShift (RHOSO) environment so that CloudKitty has real consumption data to rate. With the rating rule from the xref:creating-and-applying-a-rating-rule.adoc[previous unit] already in place, the uptime of this instance is collected by Ceilometer and rated by CloudKitty according to the cost you assigned to its flavor.

== Hands-on Activity: Launching a Test Instance

In this activity, you will upload a lightweight Cirros image to the Image service (glance), launch an instance from it using the `m1.small` flavor, and confirm that the instance is running. You will execute each command manually through the `openstackclient` pod in your RHOSO environment.

[NOTE]
====
All commands are executed through the `openstackclient` pod running in the `openstack` namespace.
====

Follow these steps:

. **Add a Cirros image to the Image service**
+
Download a lightweight Cirros image and upload it to the Image service (glance). You will use this image to launch a test instance that generates the consumption data your rating rule charges for.
+
[source,bash,role=wrap]
----
curl -L https://download.cirros-cloud.net/0.6.2/cirros-0.6.2-x86_64-disk.img | oc exec -i -n openstack openstackclient -- openstack image create --disk-format qcow2 --container-format bare --public cirros
----

. **Create a test instance**
+
Launch an instance named `test-vm` using the Cirros image and the `m1.small` flavor. This instance generates the uptime metrics that CloudKitty collects and rates.
+
[NOTE]
====
Use the `m1.small` flavor to match the rating rule you created in the previous unit. The `m1.tiny` flavor is too small to boot the Cirros image.
====
+
[source,bash,role=wrap]
----
oc exec -n openstack openstackclient -- openstack server create --flavor m1.small --image cirros --network private test-vm
----

. **Confirm the instance is running**
+
Check that the instance reached the `ACTIVE` state. It may take a minute or two to boot.
+
[source,bash,role=wrap]
----
oc exec -n openstack openstackclient -- openstack server show test-vm -c name -c status -c flavor
----
+
Example output:
+
[source,bash]
----
+--------+----------+
| Field  | Value    |
+--------+----------+
| flavor | m1.small |
| name   | test-vm  |
| status | ACTIVE   |
+--------+----------+
----

Once the instance is `ACTIVE`, it starts generating uptime metrics. CloudKitty collects and rates these metrics on a periodic cycle, so it may take a few minutes before rated consumption data appears.

[TIP]
====
If the instance status is `BUILD`, wait a moment and run the `openstack server show` command again. If it reaches `ERROR`, the flavor is likely too small to boot the image -- delete the instance and retry with the `m1.small` flavor.
====

== Automation Alternative

The repository you cloned in the xref:setting-up-the-lab-environment-for-chargeback.adoc[lab setup unit] includes a playbook that automates all the manual steps above. It downloads the Cirros image, uploads it to the Image service, launches the instance, and waits for it to become `ACTIVE`.

To launch the test instance automatically:

[source,bash,role=wrap]
----
ansible-playbook create-test-instance/create-test-instance.yml
----

You can customize the playbook variables to use a different image, flavor, or instance name:

[source,bash,role=wrap]
----
ansible-playbook create-test-instance/create-test-instance.yml -e flavor_name=m1.medium -e instance_name=demo-vm
----

The playbook supports the following variables:

[cols="1,1,2"]
|===
| Variable | Default | Description

| `openstack_namespace` | `openstack` | OpenShift namespace for the OpenStack pods
| `image_name` | `cirros` | Name of the image to create
| `image_url` | Cirros 0.6.2 download URL | Source image to upload to the Image service
| `flavor_name` | `m1.small` | Flavor to launch the instance with
| `instance_name` | `test-vm` | Name of the test instance to launch
| `network_name` | `private` | Network the instance attaches to
|===

[NOTE]
====
Keep the `flavor_name` in sync with the flavor used by your rating rule so the rule applies to the instance you launch.
====

If you made a mistake and need to start over, remove the test instance and image with the cleanup playbook, then run the create playbook again:

[source,bash,role=wrap]
----
ansible-playbook create-test-instance/cleanup-test-instance.yml
----

In the next unit, you will validate your rating configuration and confirm that CloudKitty is rating the consumption generated by this instance.
